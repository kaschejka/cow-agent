# Еноты-агенты — карточная игра

Веб-версия карточной игры **«6 берёт!»** (6 nimmt): игроки одновременно выкладывают карты,
и тот, кто вынужден забирать ряд с «пончиками» (штрафными очками), набирает их как можно меньше.

## Возможности

- **Соло-режим** — партия против ботов прямо в браузере, без регистрации
- **Сетевая игра** — комнаты до 4 игроков, кодовое слово для входа, список открытых комнат
- **Чат в комнате** — со встроенным серверным фильтром мата (антиматом)
- **Авторизация**: гость, логин/пароль, Яндекс и VK OAuth
- **Рейтинг place-Elo и статистика** — места/дельты в сводках, профиль с итогами, «Зал славы» с топами за день и неделю
- Боты подхватывают выбывших игроков, «реванш» после партии (вдвоём, по обоюдному согласию), автовыгладка последней карты, автопропуск хода по таймауту
- Без сборки и зависимостей на клиенте — чистые HTML/CSS/JS

## Требуемое ПО

| Компонент | Версия | Зачем нужен |
|---|---|---|
| PHP | 8.1+ | Backend (`api.php`); расширения: `pdo_mysql`, `redis` (phpredis), `mbstring` |
| MySQL | 5.7+ / 8.0 | Учётные записи пользователей, очередь фоновых задач (outbox) |
| Redis | 6.0+ | Сессии, состояние комнат, чат, блокировки, быстрая доставка задач |
| SMTP-сервер | — | Письма подтверждения регистрации (любая учётка: Яндекс, Gmail, свой MTA) |
| Веб-сервер | Apache 2.4+ или nginx 1.20+ | раздача статики и запуск `api.php`; локально достаточно `php -S` |
| CLI PHP | тот же бинарник | воркер фоновых задач `worker.php` |

Клиентская часть не требует Node.js и каких-либо сборщиков.

## Установка

1. Скопируйте файлы проекта в каталог, который будет корнем сайта,
   например `/var/www/cow-test` (Linux) или `C:\www\cow-test` (Windows).
2. Создайте базу данных (таблица `users` создаётся автоматически при первом обращении):

   ```sql
   CREATE DATABASE IF NOT EXISTS cows
     CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```

3. Скопируйте `.env.example` в `.env` и укажите свои подключения.
4. Настройте веб-сервер — варианты ниже (Apache или nginx + php-fpm).

Важно: из PHP должен исполняться только `api.php`, а доступ к `.env*` извне
обязательно закрывается — примеры ниже это учитывают.

### Apache 2.4

Виртуальный хост (mod_php; для php-fpm см. комментарий внутри):

```apache
<VirtualHost *:80>
    ServerName cows.local
    DocumentRoot "/var/www/cow-test"

    <Directory "/var/www/cow-test">
        Options -Indexes
        AllowOverride None
        Require all granted
    </Directory>

    # не отдавать .env и другие точечные файлы
    <FilesMatch "^\.">
        Require all denied
    </FilesMatch>

    # если PHP работает через php-fpm (mod_proxy_fcgi), вместо mod_php:
    # <FilesMatch "\.php$">
    #     SetHandler "proxy:unix:/run/php/php8.2-fpm.sock|fcgi://localhost"
    # </FilesMatch>

    ErrorLog ${APACHE_LOG_DIR}/cows_error.log
</VirtualHost>
```

На Windows пути к каталогу и сокету заменяются на диск/путь (`C:/www/cow-test`)
и TCP-адрес пула php-fpm (`fcgi://127.0.0.1:9000`).

### nginx + php-fpm

```nginx
server {
    listen 80;
    server_name cows.local;
    root /var/www/cow-test;
    index index.html;

    # исполняется только api.php
    location = /api.php {
        include fastcgi_params;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;   # либо 127.0.0.1:9000
        fastcgi_param SCRIPT_FILENAME $document_root/api.php;
        fastcgi_read_timeout 65s;
    }
    location ~ \.php$ { return 404; }

    # скрыть .env* и прочие точечные файлы
    location ~ /\. { deny all; access_log off; log_not_found off; }
}
```

### Локальная разработка без веб-сервера

Нужны запущенные локально MySQL и Redis:

```bash
php -S localhost:8000
```

Откройте http://localhost:8000. Встроенный сервер годится только для разработки.

## Размещение в VK (Mini Apps)

При запуске из VK игра открывается в iframe с подписанными параметрами
(`vk_app_id`, `vk_user_id`, `sign`, …). Клиент (`auth.js`) видит эти параметры
и выполняет **тихий вход**: через vk-bridge получает имя пользователя и шлёт
`authVkMini`. Сервер проверяет SHA256-подпись параметров секретом приложения,
находит или **автоматически создаёт** аккаунт (провайдер `vkmini`) — без формы
регистрации, e-mail и писем. Имя подтягивается из профиля при каждом входе.

Настройка:

1. Создайте приложение типа «Мини-приложение VK» на https://dev.vk.com.
2. Впишите его `VK_APP_ID` и `VK_APP_SECRET` в `.env` — секрет обязателен для
   проверки подписи, без него тихий вход отключён.
3. В настройках приложения укажите домен, где размещена игра (требуется HTTPS).
4. **Вход через VK-кнопку на обычном сайте** (`oauth.vk.com/authorize`) требует,
   чтобы `redirect_uri` был зарегистрирован в настройках приложения VK
   (раздел «Open API» / «Сайт») — иначе VK отвечает
   `invalid_request: redirect_uri is incorrect`. Укажите там точный адрес сайта
   (`https://example.com/`), он же в `VK_REDIRECT_URI` / адресе страницы.

Подделать `vk_user_id` нельзя: подпись считается от всех `vk_*`-параметров
секретом приложения. Вход через OAuth-кнопку «VK» на обычном сайте работает
отдельно и тоже не требует подтверждения почты. Для Яндекс Игр аналогично
работает `authYandex` (SDK Яндекс Игр).

## Подтверждение e-mail и фоновые задания

### Как работает регистрация

1. Пользователь указывает логин, пароль, **e-mail** и имя.
2. В одной транзакции MySQL создаются: учётка (`users`, `email_verified=0`,
   случайный `confirm_token`) и задача на письмо (таблица `jobs`) — outbox-паттерн,
   поэтому письмо не потеряется даже при падении Redis или воркера.
3. Воркер отправляет письмо со ссылкой `api.php?action=confirm&token=...`.
4. Переход по ссылке активирует аккаунт; до этого вход блокируется (403),
   а на форме входа появляется кнопка «Отправить письмо ещё раз» (не чаще
   раза в 5 минут).
5. Неподтверждённые аккаунты старше 14 дней удаляются воркером — логин и
   почта освобождаются.

### Воркер `worker.php`

```bash
php worker.php
```

Долгоживущий процесс. Доставка задач двухуровневая:

- **быстрый путь** — Redis-список `jobs:queue` (воркер спит в `BRPOP`);
- **страховка** — свёрка по БД раз в 5 сек: задачи со статусом `pending`
  и наступившим `next_attempt_at` берутся прямо из MySQL.

Неудачная попытка → экспоненциальный backoff (1→2→4→8 мин), после 5 неудач
статус `failed` с текстом ошибки. Продакшен-запуск: systemd/supervisor;
на Windows — «Планировщик заданий» с командой `php -f D:\путь\worker.php`.

### Добавление новых фоновых задач

Очередь универсальная, не только для писем:

```php
jobEnqueue('stats.aggregate', ['day' => '2026-08-24']);
```

и обработчик в `$handlers` внутри `worker.php`. Если когда-нибудь понадобится
RabbitMQ/AMQP — меняются только транспортные функции `jobEnqueue/jobClaim`,
таблица `jobs` и хендлеры остаются без изменений.

## API

Единая точка: `POST /api.php`, тело — JSON с полем `action`. Ответ — JSON c `ok: true/false`.

### Авторизация

| action | Параметры | Описание |
|---|---|---|
| `register` | `login, password, email, name?` | создаёт неподтверждённый аккаунт и ставит письмо в очередь |
| `login` | `login, password` | вход; до подтверждения e-mail — 403 |
| `logout` | `authToken` | завершение сессии |
| `me` | `authToken` | текущий пользователь |
| `resend` | `login` | повторное письмо подтверждения (не чаще раза в 5 мин) |
| `confirm` (GET) | `token` в URL | активация аккаунта по ссылке из письма (HTML-страница) |
| `authConfig` | — | отдаёт `vkAppId` (настроен ли VK-вход) |
| `authYandex` | `yaId, name?` | вход через Яндекс |
| `authVk` | `code, redirectUri` | обмен VK OAuth-кода на сессию (кнопка «VK» на обычном сайте) |
| `authVkMini` | `params, user.name?` | тихий вход внутри VK Mini Apps: проверяет подпись запуска и **автоматически** создаёт аккаунт с именем из профиля VK — без e-mail и писем |

### Комнаты и игра

| action | Параметры | Описание |
|---|---|---|
| `create` | `authToken, max?` | создать комнату, в ответе код комнаты и игровой `token` |
| `rooms` | — | список открытых комнат |
| `join` | `room, authToken` | вход в комнату (только до старта) |
| `state` | `room, token` | полное состояние для игрока (поллинг) |
| `play` | `room, token, card` | выложить карту за ход |
| `choose_row` | `row` | выбрать ряд при конфликте (фаза `choose_row`) |
| `next_round` | — | хост начинает следующий тур после паузы |
| `rematch` | — | реванш: только при игре вдвоём (без ботов) и после подтверждения обоими игроками |
| `leave` | — | выход; место занимает бот |

### Чат

| action | Параметры | Описание |
|---|---|---|
| `chat` | `room, token, text` | отправить сообщение (до 200 символов); текст проходит антимат |

## Рейтинг и статистика

Система — попарный Эло по местам (place-Elo): после партии каждая пара игроков
обрабатывается как микро-матч по итоговым местам. `K = 24`, стартовый рейтинг
`1000`, дельты нулесуммарны.

Рейтинговуется **любая сетевая партия между живыми игроками** (в финале их
должно быть минимум двое; матчи только против ботов не считаются). Гость без
аккаунта участвует с базовым рейтингом 1000: он влияет на дельты соперников и
видит свой результат, но собственных строк в БД не имеет — в таблице рейтинга
и топах его нет. Строка рейтинга создаётся при регистрации аккаунта; клиенты
обязательно передают `authToken` в сетевых запросах, иначе сервер считает
игрока гостем. Счётчиками заборов рядов (`sixth_takes`, `forced_takes`)
игроки обмениваются в течение всей партии.

Таблицы БД:

- `games` — завершённые рейтинговые партии (`room_code`, `finished_at`)
- `game_players` — результат игрока в партии: место, штраф, заборы,
  `rating_before`/`rating_after` (история для будущих графиков)
- `ratings` — агрегаты: рейтинг, партии/победы/топ-3, сумма штрафа,
  лучший/худший результат, текущая и лучшая серия побед, счётчики заборов

Где видно в интерфейсе:

- ★рейтинг рядом с именами соперников; места 🥇🥈🥉 и дельта ★±N в сводках тура и игры
- профиль в главном меню: рейтинг, партии/победы/winrate, средний штраф,
  лучший/худший результат, серии, заборы рядов

### Зал славы

Кнопка «🏆 Топы» в ряду выбора типа игры открывает вкладки:

- **☀️ Сегодня** / **📅 За неделю** — топ-10 за период по трём номинациям:
  прирост ★рейтинга, «Самый аккуратный енот» (наименьший средний штраф),
  «Повелитель Пончиков» (больше всех штрафных)
- **🏆 Топ по рейтингу** — все рейтинговые игроки (до 100 позиций) плюс ваша
  собственная позиция: место считается среди всех игроков с партиями
  (`COUNT(rating > мой) + 1`, при равном рейтинге место делится)

### Экшен `tops`

| action | Параметры | Описание |
|---|---|---|
| `tops` | `authToken?` | публичный; отдаёт `day`/`week` (по 3 топ-листа), `board` (топ-100: имя, рейтинг, партии), `total`, `you` (место/рейтинг или `null`) |

Поля рейтинга также приходят в ответах `me`/`login`/`register` (`rating`,
`stats{...}`) и в `state` у каждого игрока (`rating`, `ratingDelta`).

## Антимат

Фильтр работает на сервере (`api.php`, функции `filterProfanity*`) — сообщение
сохраняется уже очищенным, клиентские обходы невозможны.

Что умеет:

- нормализация: регистр, ё→е, leet/транслит (`ху@`, `xyu`, `п0издец`), схлопывание повторов букв
- маскировка с сохранением структуры: «б*** проиграл»
- разнесённые по словам буквы («х у й») — сообщение целиком заменяется звёздочками
- защита от ложных срабатываний: «хлебе», «рубля», «мебель», «Уйгурский» проходят

Словари для расширения: константы `PROFANITY_STEMS`, `PROFANITY_JOIN`,
`PROFANITY_LATIN` и правила в `profanityTokenBad()`.

## Разработка и отладка

- Сборка не нужна: правьте файлы и обновляйте страницу (`Ctrl+F5`).
- Версии статики: скрипты и стили подключаются с параметром `?v=ГГГГММДДбуква`
  (см. `index.html`) — при релизе поднимайте суффикс, тогда обычный `F5`
  подтягивает свежие файлы без жёсткого обновления.
- Быстрая проверка API из консоли:
  ```bash
  curl -d "{\"action\":\"rooms\"}" http://localhost/api.php
  ```
- Логи PHP смотрите в error.log виртуального хоста (Apache) или в журнале php-fpm/nginx.
- Типовые ошибки:
  - «Хранилище недоступно» — Redis не запущен или неверный `REDIS_HOSTS/PORT`;
  - «База данных недоступна» — MySQL не запущен или неверные `DB_*`;
  - письма не приходят — проверьте, запущен ли `worker.php`, и статус задач
    в таблице `jobs` (`failed` хранит текст последней ошибки);
  - пустой экран/старый вид — жёсткое обновление кэша браузера.
